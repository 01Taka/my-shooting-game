# 7シーン構成の理由と静止画面オーバーレイによるUX設計

本ゲームがなぜ単一の大きな Scene ではなく、7つの独立したシーンに細かく分割されているのか、その設計意図とUX（ユーザー体験）の思想です。

---

## 1. シーン分割の設計思想

単一の Scene（例: `MainScene`）にすべてのロジックを詰め込むと、「ゲーム更新中にポーズ画面の入力をどう扱うか」「タイトル画面の描画処理がゲーム本体に混ざる」といったスパゲッティコードに陥ります。

そこで、**「ライフサイクルと描画レイヤーの独立性」** を基準にシーンを分割しました。

```
[初期化]
PreloadScene (ロード画面)
    │ scene.start
    ▼
[メイン画面]
TitleScene (タイトル) ──scene.start──> GameScene (ゲーム本体)
                                          │
                                          ├── [並行起動] UIScene (HP/スコア/ポーズボタン)
                                          ├── [並行起動] ControllerScene (タッチ時のみ)
                                          └── [ゲームオーバー時] ResultScene (静止画面上に重ねる)
```

---

## 2. なぜ「オーバーレイ方式」を採用したのか？

### 従来の設計（画面切り替え方式）の問題点

ゲームオーバー時に `scene.start("ResultScene")` を呼ぶと、それまでプレイしていたゲーム画面が破棄され、真っ暗な背景に「GAME OVER」の文字とボタンだけが表示されます。  
これでは、「プレイヤーがどこで被弾したのか」「どんな盤面で終わったのか」という臨場感が失われてしまいます。

### 本設計の UX（静止画面オーバーレイ方式）

1. プレイヤーのHPが0になった瞬間、`this.physics.pause()` および `this.scene.pause("GameScene")` を実行し、**ゲーム画面の時間をピタッと止めます**。
2. その状態のまま、`this.scene.launch("ResultScene")` を実行します。
3. `ResultScene` は背景を半透明の黒（`0x020617, 0.8`）で覆い、ダイアログを表示します。

**結果**: プレイヤーは **「自分が敵にやられた最後の瞬間を背景に見ながら」** リザルト画面やスコア、再挑戦ボタンを操作できます。これにより、アーケードゲームのようなリッチで没入感の高いゲーム体験が生まれます。

---

## 3. なぜ ControllerScene を独立させたのか？

バーチャル十字キー（D-Pad）やショットボタンを `GameScene` 内に直接描画するのではなく、独立した `ControllerScene` として切り出しています。

### メリット

1. **デバイスの動的切り替え**:  
   タッチ端末（スマホ・タブレット）を検知したときだけ `this.scene.launch("ControllerScene")` を呼び出せばよく、PC（キーボード操作）では最初からコントローラーを非表示にできます。
2. **描画レイヤーの最前面保証**:  
   ゲーム内の敵や弾、エフェクトが増えても、コントローラーボタンがゲームオブジェクトの背後に隠れてしまうことがありません。
3. **入力の抽象化**:  
   `ControllerScene` は `{ left, right, up, down, shoot }` という純粋な入力フラグをイベント送信するだけなので、キーボード入力と同じ形式で `GameScene` に渡すことができます。
